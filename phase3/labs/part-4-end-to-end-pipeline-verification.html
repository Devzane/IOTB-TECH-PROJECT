1. Lifecycle Overview

The ultimate benchmark of an enterprise DevOps engineer is an autonomous delivery system that requires zero manual SSH intervention during standard releases. In this final lab, we test the entire pipeline from git commit to live browser verification.

Success Criteria Definition

A successful project demonstrates that when a fellow pushes an application update to GitHub, GitHub Actions automatically builds the new image, pushes it to ECR, and deploys the updated application to EC2 with zero manual commands.

4. Tracing Real-Time Workflow Logs

Navigate to GitHub > Actions and watch the execution unfold. The pipeline progresses through both stages:

  1. Job 1: Build & Push Images to Amazon ECR

    Docker Buildx compiles the Next.js standalone bundle and pushes tags zeetafin-frontend:<commit-sha> and zeetafin-frontend:latest.

  2. Job 2: Deploy to AWS EC2 Infrastructure

    GitHub Actions establishes an SSH connection, copies the production manifests, and runs deploy.sh.

  3. Automated External Availability Smoke Check

    The runner sends an HTTP GET request to http://${{ secrets.EC2_HOST }}:3000 and verifies an immediate HTTP 200 OK.

6. External Smoke Testing with curl

From your local laptop terminal, probe the public EC2 IP address:

Terminal (Local Laptop) BASH / POWERSHELL 
curl -I "http://<EC2_PUBLIC_IP>:3000"
curl -I "http://<EC2_PUBLIC_IP>:3001/api/docs"

Both endpoints must return HTTP/1.1 200 OK.

7. Live Browser Verification

Open your browser and navigate to:

  • ZeetaFin ERP Frontend: http://<EC2_PUBLIC_IP>:3000

Verify that your new update (e.g. the Release v1.1.0 badge) renders immediately in the browser without having had to restart any servers by hand.

8. Failure Scenarios & Incident Drills

High-performing DevOps engineers test failure paths just as thoroughly as happy paths. Here is how our architecture responds to common incidents:

Incident Drill Pipeline Response Production Safety Guarantee
Syntax error in TypeScript code npm run build fails inside Docker Buildx during Job 1. EC2 is never touched! The existing production application continues running unaffected.
EC2 SSH port closed by mistake Job 2 fails during SSH connection timeout. GitHub Actions alerts operator; image is safely preserved in ECR.
Database container crash Docker healthcheck detects failure; dependent containers restart automatically via restart: unless-stopped. Data is persisted on EBS volume zeetafin_prod_pgdata.
